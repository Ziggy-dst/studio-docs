# 轻度策略系统设计模式

## 核心理念

**轻度策略 ≠ 简单策略**

轻度策略的目标是：新玩家 5 分钟内懂规则，100 小时后仍有新发现。关键不是规则少，而是规则的**交互密度高**——少量规则产生大量有意义的情境。

---

## 核心循环设计

### 核心决策循环模板

每轮游戏的基本节拍：

```
[信息获取] → [资源获取] → [资源转化] → [目标提交] → [反馈/奖励]
     ↑                                                        |
     └────────────────────────────────────────────────────────┘
```

**每个环节的设计要求**：

| 环节 | 设计目标 | 常见失误 |
|------|---------|---------|
| 信息获取 | 给玩家足够信息做决策，不要给过量 | 信息墙：太多UI元素，玩家不知看哪 |
| 资源获取 | 让选择有意义（选A就不能选B） | 全都能拿：资源无限，决策无意义 |
| 资源转化 | 展示不同转化路径的价值差异 | 最优解唯一：总有一条路更好 |
| 目标提交 | 即时反馈让玩家感受进展 | 目标太远：玩家感觉努力没有回报 |

### 核心循环长度

| 类型 | 单循环时长 | 适合场景 |
|------|-----------|---------|
| 超短循环 | 5-30秒 | 动作策略、实时游戏 |
| 短循环 | 1-5分钟 | Roguelite、回合制 |
| 中循环 | 10-30分钟 | 单局完整游戏（如《Slay the Spire》） |
| 长循环 | 数小时 | 建设经营类 |

**轻度策略推荐**：中循环 + 嵌套短循环（每局30分钟内，内部有5分钟节拍）

## 资源系统设计

### 资源类型矩阵

资源的两个维度：

```
                 可直接使用
                     ↑
    行动资源          |          消耗资源
  （AP/行动点）       |        （金币/材料）
                     |
可再生 ─────────────────────────── 不可再生
                     |
    时间资源          |          存储资源
  （回合/时钟）       |        （背包/仓库）
                     ↓
                 需要转化使用
```

**轻度策略建议**：最多 3 种资源类型，且每种类型有清晰的主要用途。

### 经济系统三要素

1. **生产**：资源从哪来，产出速率是多少
2. **消耗**：资源用在哪，消耗速率是多少
3. **转化**：如何把资源 A 变成资源 B（这里产生策略选择）

**黄金法则**：消耗速率 ≈ 生产速率 × 0.8（玩家永远轻微感到压力，但不会崩溃）

## 策略空间设计

### 策略路径检验

一个健康的策略空间至少有 3 条可行路径，且各有适用情境：

```
激进路线：高风险，高回报，要求技巧
保守路线：低风险，稳定回报，容错率高
机会路线：依靠即时判断，利用当前局面的特殊优势
```

**检验方法**：
- 用"激进路线"通关：有没有有效的破敌策略？
- 用"保守路线"通关：不冒险能不能赢？
- 完全随机决策：多少局能赢（如果 >20%，说明策略深度不够）

### 消除支配策略（Dominant Strategy）

**支配策略**：一个策略在所有情境下都优于其他选项。

**消除方法**：

| 方法 | 说明 | 示例 |
|------|------|------|
| 情境依赖 | 策略效果依赖当前局面 | 攻击牌面对高防目标变弱 |
| 机会成本 | 选A就无法同时选B | 专注一种资源就放弃其他 |
| 时机窗口 | 好策略只在特定时机有效 | 开局强但后期弱 |
| 对手反制 | 有专门克制该策略的选项 | 石头剪刀布 |

### 涌现深度（Emergent Depth）

少量规则产生复杂局面，是轻度策略的核心魅力。

**设计技巧**：
- 规则之间有**交互**（A+B产生C效果，而不是A和B各自独立）
- 玩家可以**组合**规则创造意料之外的路线
- 局面**不可预测**但**可解释**（结果出现后玩家能理解原因）

## 认知负担控制

### 同屏信息量

| 信息类别 | 推荐数量 |
|---------|---------|
| 主要资源显示 | ≤ 3 种 |
| 同时活跃选项 | ≤ 5 个 |
| 影响当前决策的规则 | ≤ 3 条 |
| 可见的未来事件 | ≤ 3 个 |

**渐进式信息揭示**：先学会 A，再引入 B，用 B 的时候 A 已经是肌肉记忆。

### 规则复杂度层级

```
核心规则（必须在第一局学会）
├── 基础交互规则（前 3 局内学会）
│   ├── 进阶策略规则（10 局内学会）
│   │   └── 专家级组合技（100 局仍在发现）
```

**轻度策略的上限**：核心规则不超过 5 条，基础交互规则不超过 10 条。

## 设计模式库

### 模式一：强制压力（Forced Efficiency）

每轮都有让玩家"用完资源"的压力，剩余资源下一轮消失。

**效果**：每个决策都有代价，避免"存钱"拖延游戏节奏。

**示例**：每回合有固定行动点，用不完就浪费了；《Slay the Spire》的手牌每回合结束后丢弃。

### 模式二：动态目标（Dynamic Goals）

玩家的目标不是固定的，会随游戏进程变化或由玩家选择。

**效果**：每局面对不同挑战，增加重玩性；玩家可以根据当前局面选择目标，增加策略感。

**示例**：根据当前手牌/资源决定"做哪个目标"而不是追求单一固定目标。

### 模式三：限制创造力（Constraint as Catalyst）

给玩家施加额外限制，迫使探索不常用的策略路线。

**效果**：突破"最优路线"思维定势，增加策略多样性。

**示例**：Roguelite 中的特殊诅咒/挑战；每个关卡改变一条核心规则。

### 模式四：风险/收益坡度（Risk/Reward Gradient）

每个操作都有对应的风险-收益比，玩家可以选择冒多大的险。

**效果**：不同风险偏好的玩家都有适合自己的路线。

**示例**：低成本稳定来源 vs 高成本高品质来源；抢先行动有奖励但有风险。

### 模式五：雪球-纠正机制（Snowball with Catch-up）

领先者获得优势，但游戏设计有一定的弱者保护，避免完全碾压。

**适用场景**：主要用于多人游戏，但在单人游戏中也适用（防止某条路线过于强势）。

## 节奏设计

### 紧张-释放节奏

好的策略游戏有紧张与释放的节奏，不是持续高压。

```
紧张 → 资源稀缺、目标截止、风险决策
释放 → 目标完成、获得资源、局面改善
```

**推荐节奏**：每 2-3 分钟有一次"小释放"（完成一个小目标），每 10-15 分钟有一次"大释放"（完成一个阶段性目标）。

### 开局-中局-结局设计

| 阶段 | 设计重点 | 常见问题 |
|------|---------|---------|
| 开局 | 快速引入核心循环，制造早期兴趣点 | 太慢热：前 5 分钟无聊 |
| 中局 | 策略选择的主战场，选项最丰富 | 中局拖沓：玩家感觉在"做功课" |
| 结局 | 早期决策的集中体现，张力最高 | 结局虎头蛇尾：结果和过程脱节 |

## 常见设计失误

### 失误一：规则太多

**症状**：需要 30 分钟教程才能开始游戏；玩家看手册。

**解决**：把规则砍到最少，用自然探索代替说明文字。

### 失误二：唯一最优解

**症状**：高手玩家总走同一条路；初次游戏没有探索欲。

**解决**：确保至少 3 条可行路线，并让每条路线在某些情境下最优。

### 失误三：策略与运气比例失衡

**运气太多**：努力无回报，感觉不公平。
**运气太少**：每局感觉一样，缺乏新鲜感。

**推荐比例**：轻度策略游戏，策略影响力 60-70%，随机/运气 30-40%。

### 失误四：反馈不清晰

**症状**：玩家不知道自己的决策是否正确；游戏结束不知道哪里做错了。

**解决**：每个重要决策都有清晰的即时反馈，即使后果是延迟的。
