# 轻量数值平衡指南

## 核心理念

**独立游戏的平衡目标不是"精确"，而是"有意义"。**

数值平衡的真正目的：让每个选择都值得考虑，让玩家感觉自己的决策有影响力，让随机性感觉公平而不是残忍。

---

## 基准单位法

### 建立基准

所有数值设计从**最简单操作的收益**出发：

1. 确定"基础动作"：游戏中最基本的一次操作是什么？
2. 给这个动作定一个基准收益值（推荐：1 或 10 的整数倍）
3. 所有其他数值以基准的**倍数**表达

**示例**：
- 基础操作：抽一张牌，成本 1 AP，收益 = "1 个普通资源"
- 升级操作：抽一张稀有牌，成本 3 AP，收益 = "3-4 个普通资源等值"
- 终极操作：抽传说牌，成本 8 AP，收益 = "10 个普通资源等值"

### 数值规模选择

| 规模 | 推荐情境 | 示例 |
|------|---------|------|
| 个位数（1-10） | 资源、属性 | 力量 3，防御 2 |
| 十位数（10-100） | 血量、金币 | HP 50，金币 30 |
| 百位数（100-1000） | 分数、经验 | 分数 500，经验 200 |

**选择原则**：用最小的数字能表达的，就不要用大数字。20 比 2000 更直观。

## 经济平衡

### 收支平衡分析

**目标状态**：玩家始终感到"刚好够用，但需要做选择"。

```
理想区间：玩家资源 = 目标需求的 80-120%

过剩（>150%）：游戏太简单，决策无意义
紧张（50-80%）：产生压力感，需要效率
危机（<50%）：要么挑战性强，要么设计有问题
```

**如何测试**：
1. "松弛型"玩法：每次都选最稳妥的操作，资源够用吗？
2. "激进型"玩法：每次都追求最大收益，是否可持续？
3. 平均型：中等操作，10 局后资源趋势如何？

### 奖励规模设计

奖励的心理感知比绝对数值更重要：

| 奖励类型 | 设计原则 |
|---------|---------|
| 基础奖励 | 让玩家感觉"值了"，不要让人觉得太少 |
| 超额完成奖励 | 比基础奖励高 50-100%，让卓越有意义 |
| 连击/组合奖励 | 乘法效果（×1.5, ×2），比加法更有爽感 |
| 风险成功奖励 | 至少是"安全路线"的 2 倍，否则没人冒险 |

## 概率设计

### 概率直觉校正

玩家对概率的直觉感知与数学不符：

| 实际概率 | 玩家感知 |
|---------|---------|
| 10% | "基本不会发生" |
| 25% | "偶尔会发生" |
| 50% | "大概一半" |
| 75% | "经常发生" |
| 90% | "几乎总是" |

**设计建议**：关键保底机制的触发概率不要低于 10%，否则玩家感觉从不触发。

### 保底机制设计

**为什么需要保底**：纯随机会导致极端不好的运气，毁掉玩家体验。

**保底模式**：

```
累积保底：连续 N 次未触发后，第 N+1 次必定触发
软保底：概率随失败次数上升（每失败一次，概率+X%）
硬保底：超过 N 次必定出现好结果
```

**设计建议**：
- 对核心机制用累积保底（保证体验完整性）
- 对奖励机制用软保底（保证感觉公平）
- 保底触发时不要让玩家知道（增加自然感）

### 随机性来源分类

| 类型 | 特点 | 适用场景 |
|------|------|---------|
| 输入随机（Input Randomness） | 轮到玩家决策前随机发生 | 开局抽牌、随机地图 |
| 输出随机（Output Randomness） | 玩家决策后随机发生 | 攻击是否暴击 |

**设计建议**：轻度策略优先用**输入随机**（玩家能适应随机局面），减少**输出随机**（决策后被随机否定体验差）。

## 策略有效性检验

### 支配策略检验

**方法**：列出所有可行策略，对比在各种初始局面下的胜率。

```
策略 A：在情境 1 最优，情境 2 次优，情境 3 较差
策略 B：在情境 1 较差，情境 2 最优，情境 3 最优
策略 C：在所有情境下均次于 A 或 B → 这是支配策略，B应当被删除或调整
```

**修复方法**：给弱势策略加"情境加成"而非全局提升。

### 有效选择密度

**目标**：每 N 个选项中，至少有 K 个值得认真考虑。

| 游戏类型 | 推荐密度 |
|---------|---------|
| 卡牌构筑 | 每 5 张牌至少 2 张有用 |
| 建造/经营 | 每 4 个建筑至少 2 个常用 |
| 升级选择 | 每次 3 选 1，3 个都应该有价值 |

## 难度曲线设计

### 标准难度曲线

```
难度
  ↑
  │         /‾‾‾‾\      /‾‾‾‾\
  │    /‾‾\/      \    /      \____
  │   /              \/
  │  /
  └────────────────────────────→ 时间/进度

  开局        中期波动      后期稳定上升
```

**关键原则**：
- 开局平缓，让玩家学习规则
- 中期引入挑战，但有缓解机制
- 后期稳定上升，不要突然暴增

### 动态难度调整（可选）

如果游戏面向广泛受众，可以考虑：
- **隐式调整**：根据玩家表现微调随机数（表现差时保底稍低、好结果稍多）
- **显式调整**：难度选项，让玩家自选

**独立游戏建议**：优先做好固定难度的体验，动态难度是优化项。

## 数值调整流程

### 快速迭代原则

1. **先定性**：这个机制应该"很强"还是"情境强"？
2. **再定量**：根据基准单位设初始值
3. **极端测试**：最大化利用这个机制会怎样？最小化会怎样？
4. **微调**：每次只改一个变量，幅度不超过 ±30%

### 调整幅度参考

| 感知效果 | 调整幅度 |
|---------|---------|
| 微调（几乎感觉不到） | ≤ 10% |
| 明显调整 | 15-25% |
| 大幅重设 | 30-50% |
| 机制重新设计 | >50% → 考虑重新设计逻辑 |

## 常见数值陷阱

### 陷阱一：数字通货膨胀

**症状**：后期数字变成几百万，玩家失去感知。

**解决**：压缩数值规模，或用乘法替代加法。

### 陷阱二：一刀流最优解

**症状**：专注一个资源就能无脑赢。

**解决**：设计资源之间的转换损耗，让专注一种资源有收益但也有代价。

### 陷阱三：随机崩溃

**症状**：某一局运气极差，完全无法翻盘，玩家觉得不公平。

**解决**：保底机制 + 纠正机制（运气差时增加其他来源的补偿）。

### 陷阱四：成长曲线断崖

**症状**：某个阶段突然变得极难（通常是设计者自己熟悉了忘记调整）。

**解决**：每次大改动后重新测试全程难度曲线。
