# 选择与后果系统设计

## 核心理念

**让每个选择都有真实重量。**

选择系统的本质不是"分支剧情"，而是让玩家感受到"我的决定改变了什么"。最好的选择设计是：玩家做出选择时有清晰的理由，选择后感受到真实的影响，即使结果不好也能理解为什么。

---

## 选择点设计

### 何时呈现选择

选择不应该随时随地出现，而应该在**最有意义的时机**出现。

| 时机 | 效果 | 示例 |
|------|------|------|
| 资源紧张时 | 代价感最强 | 只剩一个物品，给谁？ |
| 信息不完整时 | 不确定性张力 | 只知道A的优点，B的情况未知 |
| 已建立感情后 | 情感共鸣最强 | 对已认识的角色做决定 |
| 时间压力下 | 直觉 vs 理性 | 限时选择，没时间细想 |

**频率控制**：
- 核心选择（影响全局）：每局 3-5 次
- 次要选择（影响局部）：每 10-15 分钟一次
- 微小选择（操作层面）：每轮都有，但代价轻微

### 选择呈现方式

**好的选择呈现**：
- 每个选项的即时代价/收益清晰可见
- 长期影响可以推断但不完全确定
- 每个选项都有合理的人会选择它的理由

**不好的选择呈现**：
- 一个选项明显更好（不是真正的选择）
- 信息完全隐藏，玩家只能猜测（是运气，不是选择）
- 选项太多，认知过载

## 后果设计

### 后果传播结构

```
选择
  ├── 即时反馈（0-5秒）：视觉/音效/数值变化，让玩家知道"做了"
  ├── 短期后果（同局内）：影响接下来几分钟的游戏局面
  └── 长期后果（跨局/全程）：影响游戏结局或后续事件
```

**轻度策略建议**：每个重要选择至少有即时反馈 + 短期后果，核心选择应有长期后果。

### 后果清晰度光谱

```
完全透明 ←————————————————————→ 完全不透明

"选A得+10金币"      "你感觉这个决定以后会有影响"
（可计算）          （叙事暗示）
```

**最佳实践**：
- 机制性后果（数值、规则变化）→ **透明**（玩家能计算）
- 叙事性后果（角色反应、故事走向）→ **半透明**（能推断，不确定）
- 惊喜性后果（意外发展）→ **不透明**（刻意隐藏，增加探索感）

## 灰色选择设计

### 为什么需要灰色选择

没有明显正确答案的选择才是真正的选择。

**灰色选择的构成**：
- 每个选项对**不同价值观的玩家**各有吸引力
- 没有哪个选项在所有维度上都更优
- 选择反映玩家的优先级，而不是测试玩家是否找到"正确答案"

### 制造灰色的方法

**方法一：不同维度的权衡**
```
选A：+资源，-时间
选B：+时间，-资源
（没有哪个在所有情境下更优）
```

**方法二：短期 vs 长期**
```
选A：现在获益大，长期代价高
选B：现在代价高，长期获益大
（取决于玩家的时间偏好和当前局面）
```

**方法三：确定性 vs 潜力**
```
选A：稳定但平庸的结果
选B：期望值相近但方差大的结果
（取决于玩家风险偏好）
```

**方法四：个体 vs 集体**
```
选A：对当前玩家最优
选B：对整体局面/故事最优
（取决于玩家的优化目标）
```

## 分支复杂度管理

### 独立游戏的分支挑战

无限分支 = 无限内容量需求。独立游戏必须用有限资源制造丰富感。

### 内容复用技术

**技术一：收束型分支（Funnel Branches）**

```
A ─┐
   ├─→ [共同节点] ─→ 后续内容
B ─┘
```

不同选择殊途同归，但中间经历不同，**旅程不同，终点相似**。

**技术二：状态影响（State Flags）**

不是真正分支，而是"记住你的选择，在后续改变细节"。

```
选择X后 → 后续所有对话稍有不同，但主线相同
```

适合低成本表现选择重量感。

**技术三：折叠分支（Diamond Branches）**

```
[选A] ─→ [不同过程] ─→ [不同结局]
[选B] ─→ [不同过程] ─→ [不同结局]
```

选择影响结局，但每条路线独立完整，总内容量 = 路线数 × 路线长度。

**适用建议**：
- 核心叙事节点：用折叠分支（2-3 个关键结局）
- 过程细节：用状态影响（丰富感，低成本）
- 局面差异：用收束型分支（不同过程，相同框架）

## 延迟后果的节奏感

### 延迟多久合适

| 延迟时长 | 效果 | 风险 |
|---------|------|------|
| 即时（<5分钟） | 清晰因果，学习价值高 | 代价感不够深刻 |
| 短期（同局，5-30分钟后） | 让玩家感受到影响 | 可能被遗忘 |
| 长期（跨局或游戏结尾） | 重量感最强 | 玩家可能不记得原始选择 |

**记忆锚设计**：长期后果发生前，给一个"提醒"，让玩家想起当初的选择。

```
示例：
游戏开始时选择了「帮助 NPC A」
→ 游戏后期 NPC A 再次出现时
→ 先有一句话："你还记得那次帮助我吗？"
→ 玩家重新想起选择，然后看到后果
```

## Inkle/Failbetter 设计模式

### Inkle 模式（叙事主导）

**核心**：玩家选择叙事路径，机制服务于叙事。

**特点**：
- 选择主要影响故事走向和角色关系
- 机制数值是叙事工具（不是策略重心）
- 情感投入是核心体验

**适用**：以故事为核心的独立游戏，如互动小说、AVG。

### Failbetter 模式（叙事+策略混合）

**核心**（来自 Fallen London / Sunless Sea 的设计思路）：
- 故事片段可反复解锁，每次体验可以不同
- 属性/资源影响可用选项（高属性解锁更多选项）
- 世界状态的变化驱动新故事出现

**特点**：
- 选择有机制代价（资源、属性）
- 叙事丰富，但单段内容较短
- 重复游玩发现新内容

**适用**：探索驱动的独立游戏，叙事内容丰富但每段较短。

## 检验清单

### 选择质量检验

- [ ] 每个选项都有玩家选择它的合理理由
- [ ] 没有"明显正确"的唯一答案（除非刻意设计）
- [ ] 选择的即时反馈清晰
- [ ] 选择的后果在合适的时机体现
- [ ] 选择数量在认知负担范围内（单次选择不超过 4 个选项）

### 分支管理检验

- [ ] 总内容量在团队可实现范围内
- [ ] 核心故事路线每条都经过完整测试
- [ ] 状态影响的细节变化丰富但不是必须体验的
- [ ] 玩家可以在不同游玩中发现新内容（重玩激励）
